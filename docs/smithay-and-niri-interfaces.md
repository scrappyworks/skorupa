# Skorupa capability audit

**Audited 27 November 2026.** Pinned Smithay supplies most of Skorupa’s Wayland dispatch, including DMA-BUF feedback, DRM syncobj timelines, image-copy capture, foreign-toplevel listing and session-lock surfaces. The largest v1 gaps are **workspace protocol implementation, explicit-sync integration with the frame loop, authorization of individual capture sources, and lock acknowledgement tied to presentation**. Niri supplies working references for workspace and capture integration. Its lock authority, host-client trust model and general-purpose IPC differ materially from the brief. ## Lock ordering, client visibility and unsafe GPU entry points

**Lock ordering is decisive.** On `UnlockAndDestroy`, Smithay verifies that the request belongs to the current lock, sets `LockStatus::Unlocked` at `session_lock/lock.rs:122`, then calls `state.unlock()` at line 123. The callback returns `()` and offers no veto. Destruction without a valid unlock marks the matching lock `Defunct` at line 142 and leaves recovery policy to the compositor. Rygiel actually sends `unlock_and_destroy()` at `app.rs:900`. For production, the compositor must consume the one-use `authd` verdict bound to instance, session, epoch and attempt before changing its authoritative lock state. Giving the renderer a standard lock object would give it an independently actionable unlock request. [Smithay request order](https://github.com/Smithay/smithay/blob/46643d2/src/wayland/session_lock/lock.rs#L117) · Rygiel call · [Protocol XML](https://raw.githubusercontent.com/wayland-mirror/wayland-protocols/main/staging/ext-session-lock/ext-session-lock-v1.xml)

**Lock acknowledgement needs a different backend completion point from niri’s.** Niri updates its per-output lock-render state from the render result or inactive-monitor condition, calls `self.unlock()` if a required locked render failed, and calls `confirmation.lock()` once the output states qualify. Actual presentation feedback is processed separately in the DRM backend. For Skorupa’s one panel, carry the lock epoch through frame submission to the matching presentation completion. A skipped or failed flip must leave the session protected. Output disappearance and suspend need explicit transitions in the brief’s ordering model. [Niri lock decision](https://github.com/niri-wm/niri/blob/02ee0585/src/niri.rs#L5131) · [DRM completion](https://github.com/niri-wm/niri/blob/02ee0585/src/backend/tty.rs#L1802) · [Lock protocol presentation requirement](https://raw.githubusercontent.com/wayland-mirror/wayland-protocols/main/staging/ext-session-lock/ext-session-lock-v1.xml)

**Global filtering has two distinct inputs.** At connection admission, the compositor supplies server-owned `ClientData`. At registry advertisement/bind, `GlobalDispatch::can_view(client, global_data)` decides whether that client can see and bind that global. The default is `true`. Smithay’s `delegate_dispatch2!` forwards to the global data’s predicate. With a filtered constructor, read the assigned role from `client.get_data()` there. Security-context supplies the creator client ID and optional launcher-supplied engine, app and instance strings. Its own manager must exclude children created through a context. Niri’s listener converts these connections into a `restricted` boolean. Skorupa needs distinct launcher, shell, portal, UI and agent admission rules, plus request-time grant checks for objects that are already bound when a grant is revoked. [wayland-server contract](https://docs.rs/wayland-server/latest/wayland_server/trait.GlobalDispatch.html) · [Pinned delegation](https://github.com/Smithay/smithay/blob/46643d2/src/wayland/dispatch2.rs#L68) · [Context metadata](https://github.com/Smithay/smithay/blob/46643d2/src/wayland/security_context/mod.rs#L51) · [niri client insertion](https://github.com/niri-wm/niri/blob/02ee0585/src/niri.rs#L3064)

## Insights

1. **Make the portal’s selected-source contract explicit before porting capture.** xdpw 0.9’s simple chooser returns an output name or an ext-foreign-toplevel identifier. Stock xdpw then uses its own Wayland connection to resolve the source. Smithay’s stock list advertises all published toplevels to an admitted list client. The brief grants the list to the shell and a *selected source* to the portal. The requester-binding patch therefore needs a defined way to resolve only that selection, enforce it when frames are requested, and revoke it on Stop. `chooser_type=simple` alone also leaves xdpw’s separate restore-data path in place. I verified the upstream paths, not a finished Skorupa patch. [Chooser contract](https://github.com/emersion/xdg-desktop-portal-wlr/blob/v0.9.0/xdg-desktop-portal-wlr.5.scd#L74) · [Source creation](https://github.com/emersion/xdg-desktop-portal-wlr/blob/v0.9.0/src/screencast/ext_image_copy.c) · [Restore handling](https://github.com/emersion/xdg-desktop-portal-wlr/blob/v0.9.0/src/screencast/screencast.c#L467) · [Smithay list fan-out](https://github.com/Smithay/smithay/blob/46643d2/src/wayland/foreign_toplevel_list/mod.rs#L335)
2. **Use niri for DMA-BUF feedback and Anvil for explicit sync.** Niri demonstrates scanout tranches and surface feedback. Anvil at the candidate revision demonstrates the eventfd capability gate and acquire blocker. Neither source establishes correct release timing on Skorupa’s eventual scanout path or 120/180 Hz performance on the target laptops. Those remain hardware acceptance tests. [Niri feedback builder](https://github.com/niri-wm/niri/blob/02ee0585/src/backend/tty.rs#L3042) · [Anvil device gate](https://github.com/Smithay/smithay/blob/46643d2/anvil/src/udev.rs#L491) · [Anvil acquire blocker](https://github.com/Smithay/smithay/blob/46643d2/anvil/src/shell/mod.rs#L143)
3. **The headless agent needs its own build decision.** The candidate compositor manifest selects `renderer_gl` and omits `renderer_pixman`. Smithay exposes Pixman as a separate feature. Niri’s headless reference constructs surfaceless EGL and GLES. Budget an agent-specific Pixman configuration and exercise capture there independently of the host DRM backend. Candidate manifest · [Smithay features](https://github.com/Smithay/smithay/blob/46643d2/Cargo.toml#L120) · [niri headless constructor](https://github.com/niri-wm/niri/blob/02ee0585/src/backend/headless.rs#L50)
4. **Two owner decisions affect v1 compatibility.** First, choose how the shell receives idle notifications given the missing constructor filter. Second, decide whether an authorized screen reader is a release requirement, including its behavior during credential entry. The first decision determines whether to write a small amount of dispatch glue. The second changes input routing and acceptance tests; niri’s **503-line** D-Bus file measures only part of that work. [Idle global](https://github.com/Smithay/smithay/blob/46643d2/src/wayland/idle_notify/mod.rs#L122) · [niri accessibility input order](https://github.com/niri-wm/niri/blob/02ee0585/src/input/mod.rs#L504) · [Orca support notes](https://github.com/niri-wm/niri/blob/02ee0585/docs/wiki/Accessibility.md#L5)
5. **Spend the lock budget on acknowledgement and recovery before visual parity.** The upstream protocol requires protected content to have been presented before `locked`. The candidate changes protocol status before calling `unlock`, and niri has an explicit failed-lock-render branch that calls `unlock()`. These three facts identify concrete tests for Skorupa’s reducer: stale verdict, UI death, failed flip, delayed completion from an older epoch, and panel loss while locking. All can be specified before the first DRM test on a live laptop.
